## Overview

The ML Platform uses a multi-layered security monitoring approach to detect, alert, and respond to
security findings across the AWS infrastructure. This document provides step-by-step procedures for
handling security incidents detected by our automated monitoring systems.

## Security Monitoring Stack

### Components

1. **AWS Security Hub**
   - Centralized security findings aggregator
   - Runs continuous compliance checks against:
     - CIS AWS Foundations Benchmark v1.4.0
     - AWS Foundational Security Best Practices v1.0.0
   - Consolidates findings from GuardDuty, Inspector, and other AWS services

2. **AWS GuardDuty**
   - Threat detection service for:
     - Unusual API calls
     - Potentially compromised EC2 instances
     - Reconnaissance activities
     - Kubernetes audit log analysis (EKS-specific)
     - S3 data access anomalies
     - Malware detection on EBS volumes

3. **AWS Inspector**
   - Automated vulnerability scanning for:
     - EC2 instances (operating system vulnerabilities)
     - ECR container images (package vulnerabilities)
     - Network exposure assessments

4. **EventBridge + SNS**
   - Real-time alerting for HIGH and CRITICAL findings
   - Email notifications to designated security contacts

Alerts flow: Security Hub/GuardDuty/Inspector → EventBridge → SNS → Email (HIGH/CRITICAL findings only)

## Severity Levels

### AWS Security Hub Severity Scale

| Severity | Score Range | Response Time | Description |
|----------|-------------|---------------|-------------|
| **CRITICAL** | 90-100 | Immediate (< 15 min) | Imminent threat requiring immediate action |
| **HIGH** | 70-89 | Urgent (< 4 hours) | Significant security risk requiring prompt attention |
| **MEDIUM** | 40-69 | Standard (< 24 hours) | Moderate risk requiring planned remediation |
| **LOW** | 1-39 | Routine (< 7 days) | Low risk, address during regular maintenance |
| **INFORMATIONAL** | 0 | As needed | Informational only, no action required |

### GuardDuty Severity Scale

| Severity | Score Range | Security Hub Equivalent |
|----------|-------------|------------------------|
| **HIGH** | 7.0-8.9 | HIGH (may be re-scored to CRITICAL by Security Hub) |
| **MEDIUM** | 4.0-6.9 | MEDIUM |
| **LOW** | 0.1-3.9 | LOW |

> **Important**: GuardDuty only produces findings with severity scores between 0.1 and 8.9. There is no
> CRITICAL severity level in GuardDuty itself. However, Security Hub may re-score GuardDuty HIGH
> findings (7.0-8.9) as CRITICAL based on additional context or enrichment from other sources.
> Always refer to Security Hub for the final severity classification used in incident response.

## Incident Response Phases

### 1. Detection & Alert

**Automated:**

- Security finding generated by Security Hub/GuardDuty/Inspector
- EventBridge rule matches HIGH/CRITICAL severity
- SNS sends email alert to security contacts

**What You'll Receive:**

```text
Subject: 🚨 Security Alert: CRITICAL Severity Finding

Title: [Finding Title]
Description: [Finding Description]
Resource: [Affected AWS Resource ARN/ID]
Region: us-west-2
Compliance Status: FAILED
Action: Review finding in AWS Security Hub console
```

### 2. Triage & Assessment

**Immediate Actions (< 15 minutes):**

1. **Acknowledge the alert** - Reply to the email or log the incident

2. **Access Security Hub Console:**

   ```bash
   # Get console URL from Terraform outputs
   cd terraform/environments/dev
   terraform output security_hub_console_url

   # Or directly:
   # https://us-west-2.console.aws.amazon.com/securityhub/home?region=us-west-2#/summary
   ```

3. **Review the finding details:**
   - Title and description
   - Affected resource(s)
   - Compliance status
   - Remediation recommendations
   - Related findings

4. **Assess impact:**
   - Is this a true positive or false positive?
   - What data/systems are at risk?
   - Is there evidence of active exploitation?
   - What is the blast radius?

5. **Determine severity and priority:**
   - Validate the assigned severity
   - Consider business context
   - Check for indicators of compromise (IOC)

### 3. Containment

**Immediate Containment (if exploitation detected):**

**For Compromised EC2/EKS Nodes:**

```bash
# Option 1: Isolate the instance (revoke security group rules)
aws ec2 modify-instance-attribute \
  --instance-id <INSTANCE_ID> \
  --groups <RESTRICTED_SG_ID>

# Option 2: Stop the instance (preserves forensics)
aws ec2 stop-instances --instance-ids <INSTANCE_ID>

# Option 3: Terminate and replace (for auto-scaled nodes)
kubectl cordon <NODE_NAME>  # Prevent new pods
kubectl drain <NODE_NAME>   # Evict existing pods
# Auto Scaling will launch replacement node
```

**For Compromised IAM Credentials:**

```bash
# Disable access keys
aws iam update-access-key \
  --access-key-id <ACCESS_KEY_ID> \
  --status Inactive \
  --user-name <USER_NAME>

# Attach deny-all policy (immediate effect)
aws iam put-user-policy \
  --user-name <USER_NAME> \
  --policy-name DenyAll \
  --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Deny","Action":"*","Resource":"*"}]}'
```

**For Exposed S3 Buckets:**

```bash
# Block public access immediately
aws s3api put-public-access-block \
  --bucket <BUCKET_NAME> \
  --public-access-block-configuration \
    BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

### 4. Eradication

**Remove the threat:**

1. **Patch vulnerabilities:**
   - Update vulnerable packages/AMIs
   - Apply security patches
   - Update container images in ECR

2. **Remove malicious artifacts:**
   - Delete backdoors, malware, unauthorized resources
   - Rotate compromised credentials
   - Revoke unauthorized access

3. **Fix misconfigurations:**
   - Update Terraform configurations
   - Apply security best practices
   - Enable required security controls

### 5. Recovery

**Restore normal operations:**

1. **Deploy fixes:**

   ```bash
   # Update Terraform configurations
   cd terraform/environments/dev
   terraform plan
   terraform apply

   # Update Kubernetes resources
   kubectl apply -f k8s/
   ```

2. **Verify remediation:**
   - Re-scan with Inspector
   - Check Security Hub compliance status
   - Test affected services

3. **Monitor for recurrence:**
   - Watch CloudWatch logs
   - Monitor GuardDuty findings
   - Check Security Hub dashboard

## Finding Type Quick Reference

| Finding Type | Severity | Immediate Action | Key Command |
|---|---|---|---|
| UnauthorizedAccess:EC2/MaliciousIPCaller | HIGH/CRITICAL | Isolate instance, snapshot, review CloudTrail | `aws ec2 modify-instance-attribute --instance-id ID --groups RESTRICTED_SG` |
| CryptoCurrency:EC2/BitcoinTool | HIGH | Stop instance, check access, terminate | `aws ec2 stop-instances --instance-ids ID` |
| Recon:EC2/PortProbeUnprotectedPort | MEDIUM | Review SG rules, restrict ports | `aws ec2 describe-security-groups --group-ids SG_ID` |
| IAM.1 Root Access Key Exists | CRITICAL | Delete root access keys immediately | `aws iam delete-access-key --access-key-id KEY_ID` |
| EC2.2 Default SG Open | HIGH | Remove all ingress/egress rules | `aws ec2 revoke-security-group-ingress/egress` |
| S3.1 Public Access Enabled | HIGH | Block public access | `aws s3api put-public-access-block --bucket NAME --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true` |
| CVE Package Vulnerability | HIGH | Update package/container image | `yum update PACKAGE` or rebuild Docker image |
| Network Exposure Port 0.0.0.0/0 | MEDIUM/HIGH | Restrict to specific IP range | `aws ec2 revoke/authorize-security-group-ingress` |
| IAM Password Policy Missing | MEDIUM | Configure via Console or Terraform | Update terraform/environments/dev/main.tf |
| CloudTrail Not Enabled | MEDIUM | Enable via Terraform | `terraform apply -var="enable_cloudtrail=true"` |

**For detailed remediation steps**, refer to AWS documentation or contact platform engineering team.

## Escalation Procedures

### When to Escalate

Escalate to senior security personnel if:

- **Active exploitation detected** (e.g., data exfiltration, lateral movement)
- **Compliance violation with legal implications** (e.g., GDPR, HIPAA)
- **Widespread impact** (affects multiple AWS accounts or critical systems)
- **Unable to contain** within response time SLA
- **Ransomware or destructive malware** detected
- **Root cause unclear** after initial investigation

### Escalation Contacts

1. **Technical Escalation:** Platform Engineering Lead
2. **Management Escalation:** Engineering Manager
3. **Legal/Compliance:** Legal Department (for compliance violations)
4. **AWS Support:** Open support case for account compromise

```bash
# - Specify: "Suspected compromise" for priority handling
```

## Post-Incident Activities

**Document incidents in:** `docs/incidents/YYYY-MM-DD-summary.md`

**Track metrics**: MTTD (detection), MTTA (acknowledgment), MTTC (containment), MTTR (remediation)

**Quarterly review**: Update Terraform configs based on root cause, review Security Hub compliance trends

## Tools and Resources

### AWS Console URLs

```bash
# Get URLs from Terraform outputs
cd terraform/environments/dev

terraform output security_hub_console_url
terraform output guardduty_console_url
```

### CLI Commands Reference

```bash
# Security Hub
aws securityhub get-findings --max-results 10
aws securityhub get-insights
aws securityhub batch-update-findings --finding-identifiers <FINDING_ID> --workflow Status=RESOLVED

# GuardDuty
aws guardduty list-findings --detector-id <DETECTOR_ID>
aws guardduty get-findings --detector-id <DETECTOR_ID> --finding-ids <FINDING_ID>
aws guardduty archive-findings --detector-id <DETECTOR_ID> --finding-ids <FINDING_ID>

# Inspector
aws inspector2 list-findings --max-results 50
aws inspector2 get-findings --finding-arns <FINDING_ARN>

# CloudTrail (for forensics)
aws cloudtrail lookup-events --max-results 50
aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=RunInstances
```

### Terraform Operations

```bash
cd terraform/environments/dev

# Enable Security Hub (if not already enabled)
terraform apply -var="enable_security_hub=true" -var="security_alert_email=your-email@example.com"

# Enable GuardDuty (30-day free trial)
terraform apply -var="enable_guardduty=true"

# Enable Inspector (after EKS nodes deployed)
terraform apply -var="enable_inspector=true"

# View outputs
terraform output
terraform output security_hub_console_url
terraform output security_alerts_topic_arn
```
